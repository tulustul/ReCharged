# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

ReCharged is an arcade combat racer (1:10 RC cars) in Rust + Bevy 0.20, with the whole UI in
React via bevy-react, physics in bevy_rapier3d and audio in bevy_kira_audio. Every asset is
generated by scripts in `tools/`; assets under `assets/` are Git LFS objects.

## Read before changing code
- `docs/PRACTICES.md`: the mandatory engineering rules (ECS conventions, error handling,
  testing, assets, UI). §1's ownership and "do not commit" rules address agents working from
  task briefs under an orchestrator.
- `docs/ARCHITECTURE.md` §1–4 (principles, layers, runtime model, `rc_core` contracts), plus the
  section for the subsystem you touch, and its design note `docs/design/<crate>.md`. Keep that
  design note current when behaviour changes.
- Bevy 0.20, bevy_rapier3d 0.37, bevy_kira_audio 0.27 and bevy-react 0.8.1 are newer than your
  training data. Check `docs/tech/*-notes.md` (start with `bevy-0.20-notes.md` §0, "traps") or
  the source in `~/.cargo/registry/src/index.crates.io-*/<crate>-<version>/` before writing an
  API call from memory. Custom shaders are **WESL** (`assets/shaders/`), not WGSL with `#ifdef`.

## Commands
```sh
cd ui && npm install && npm run build && cd ..        # UI bundle (ui/dist), needed by every game run
cargo run -p recharged -- --user-data-dir target/agent-data/<id> --exit-after 30 [flags]
cargo run -p rc_editor -- <track> [--user-data-dir <dir>] # track editor
./tools/ci.sh                                         # fmt, clippy -D warnings, workspace tests, bindings, UI
```
- Per crate: `cargo check -p <crate>`, `cargo test -p <crate>`, `cargo clippy -p <crate>
  --all-targets -- -D warnings`, `cargo fmt -p <crate>`.
- One test: `cargo test -p <crate> <name_substring>` (integration tests: `--test <file>`).
  Long simulations are `#[ignore]`d, e.g.
  `cargo test -p rc_ai --test race -- --ignored every_layout`.
- UI (in `ui/`): `npm run typecheck`, `npm test`, `npm run build`; `npm run watch` hot-reloads
  while the game runs. `ui/src/bevy.ts` is generated: after changing an rc_ui channel, run
  `cargo run -p rc_ui --example export_bindings -- ui/src/bevy.ts` (ci.sh fails if it is stale).
- Game runs: always pass `--user-data-dir target/agent-data/<id>` (never the real profile in
  `~/.config/recharged`) and `--exit-after`; `--unlock-all` reaches locked tracks.
- Release builds (`cargo build --release -p recharged`) load `ui/app.js` + `ui/vendor.js` next
  to the executable. For local runs: `ln -sfn ../../ui/dist target/release/ui`.
- All builds share `target/`. Don't set another `CARGO_TARGET_DIR`, and don't run `cargo
  clean` or `cargo update`.

## Seeing changes (visual verification)
- `--quick-race <track> [--players n] [--time t] [--weather w] --autopilot --screenshot <png>
  --screenshot-at <s> [--screenshot-every <s>]`: in-race shots.
- `--track-tour <track>`: a screenshot every 25 u along the racing line, written to
  `<user-data-dir>/captures/`.
- A specific spot in a race: `--quick-race <track> [--time t] [--weather w] --camera
  x,y,z,tx,ty,tz --screenshot <png> [--screenshot-at <settle s, default 4>]` renders one 1280×720
  shot (no HUD) from eye (x,y,z) looking at (tx,ty,tz), then quits. Indoor rooms have a ceiling
  (`room.height` in the track's `environment.ron`): keep the eye below it.
- Graphics overrides (any run): `--graphics "(preset: Low, shadows: Off, anti_aliasing: Fxaa,
  ambient_occlusion: false, bloom: false)"` (RON fields of `GraphicsSettings`, over the
  defaults rather than the profile's settings; never saved). rc_render reads the individual
  options, so a preset alone only changes the SSAO/SMAA/shadow-map detail: list the options too.
- A specific spot in the editor: point its camera through the UI script, e.g.
  `RECHARGED_UI_SCRIPT="3 editor lookAt x y z tx ty tz" cargo run -p rc_editor -- <track>
  --window 1280x720 --screenshot <png> --screenshot-at 14 --exit-after 15`. Other `editor …`
  verbs are listed in `docs/design/rc_editor.md`.
- Effects: `cargo run -p rc_vfx --example vfx_lab -- --scene <shapes|drive|sparks|items|blasts|events|weather>
  [--chase] [--slow 0.25] --screenshot <png> --screenshot-at <s> --exit-after <s>`.
- Frame times: `--bench <track>_<n>p` prints p50/p95/p99 JSON (1920×1080, vsync off). Compare
  builds A/B, alternating runs; the window size can vary between runs.
- The budget machine is an RTX 3070. Some dev work happens on an Intel Iris Xe laptop, which is
  far slower and has Mesa-specific issues.

## Architecture (big picture)
- **Layered crates, enforced by Cargo** (ARCHITECTURE §2.1): `rc_core` (contracts) → simulation
  (`rc_track`, `rc_vehicle`, `rc_input`, `rc_weather`, then `rc_race`, `rc_ai`, `rc_items`) →
  presentation (`rc_camera`, `rc_render`, `rc_vfx`, `rc_audio`) → flow (`rc_game`) → UI bridge
  (`rc_ui`) → binaries (`recharged`, whose lib assembles the app and is reused by `rc_editor`).
  Same-layer crates never depend on each other; they talk only through `rc_core` components,
  resources, messages, states and system sets.
- **Simulation is headless and deterministic.** Gameplay runs in `FixedUpdate` at 60 Hz in the
  `SimSet` stages (ARCHITECTURE §3.2), counts ticks (no wall or virtual time), draws randomness
  only from `rc_core::rng::draw(seed, tick, stream, key)`, and reads latched input intents. This
  powers the `rc_testkit` integration, determinism and soak tests. Presentation runs in `Update`
  (`InterpolateSet` → `CameraSet` → `VisualSet` → `AudioSet` → `UiSet`) and never writes gameplay
  state.
- **One writer per component or resource** (tables in ARCHITECTURE §4). Other crates *decorate*
  entities spawned by the owner through `On<Add<Marker>>` observers.
- **Session lifecycle** (ARCHITECTURE §3.1): `AppState` Boot → Menu → Loading → InRace →
  Unloading. `RaceSession` and `RaceAttempt` scope states hold `RacePhase` (Setup, Intro,
  Countdown, Racing, Finished) and `PauseState`. Attempt entities spawn in
  `OnEnter(RaceAttempt)` with `DespawnOnExit(RaceAttempt)`, session entities use
  `DespawnOnExit(RaceSession)`, and loaders report `LoadingDone(key)`.
- **Interpolated visuals:** rapier bodies are moved only by rc_vehicle, rapier and rc_track.
  rc_render spawns a visual proxy per `Interpolated` sim entity and poses it from
  `PoseHistory`. Teleports send `Teleported`.
- **Data-driven content:** RON under `assets/data/` (catalog, vehicles, props, items, AI) and
  `assets/maps/<track>/` (`track.ron` layout, `decor.ron`, `environment.ron` lighting and
  materials, baked `.irv` light). The track editor owns the map files. Each data file is
  validated by a test in its owning crate.
- **UI:** React in `ui/src/` renders to `bevy_ui` and talks to Bevy only through the generated
  `bevy.ts` client (typed channels in `rc_ui`). Navigation comes only from the `ui.nav` event.
- **Rendering:** rc_render's `quality/camera.rs` decorates every 3D view (`QualityCamera`) with
  HDR, a depth prepass (soft particles, forward decals, water, occlusion culling) and the
  per-quality post effects. A pipeline warm-up compiles every material/mesh/view combination in
  the menu and under the loading screen (`rc_render/src/lighting/warmup.rs`,
  `rc_vfx/src/warmup.rs`); a new material or effect pipeline needs an instance there, or it
  hitches mid-race.
